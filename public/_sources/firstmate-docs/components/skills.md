# Skills

Skills are focused operating playbooks.
They keep specialized procedures out of the main instructions while making those procedures easy to load when needed.

## When skills help

Use a skill when a task has a repeatable safety contract or decision process, such as:

- project management
- stuck worker recovery
- second mate provisioning
- ask-user decisions
- diagnostic reasoning
- self-update
- documentation polish

## Good skill design

A good skill has one owner, one trigger, and one clear procedure.
It should not duplicate a script's exact contract or another skill's decision policy.

## Reader shortcut

If a process feels too detailed to remember, it probably belongs in a skill or script rather than in chat memory.
